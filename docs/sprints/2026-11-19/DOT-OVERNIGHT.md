# 单票续办：范围冲突与历史值引用

只针对已经隔离的单票 `change_invoice` 路径；高级选集/规则办理继续走原合同。原始证据、产品基线和候选 14d0415 不覆盖。测试只用仓库虚构夹具，真实模型只走到原 Workbench 确认屏，统一拒绝、不批准。

## 从证据到改动

- 程序反例：旧待补已绑定 F006；当前用户更正为 F010，但模型补丁漏传票号。原 Runtime 用 F006 生成草稿。另一反例：用户给出的未引用字面新值包含企业/年月/票号，原 Runtime 能把内容当范围。旧查询引用解析失败还会在模型看到收到的办理状态前截断“一张票已知、内容待补”的对话。
- 修正：已知票号和当前明确编号冲突时，不擅自继承也不择一；撤销活动键及其来源，直到提供可验证的目标。精确来源的自由文本不再独自提供办理范围；相同字符出现在显式目标和有引号的新值时，显式目标仍有效。已有唯一待补目标时，不能让**失败**的展示引用解析提前终止模型；未授予旧查询引用或其他权限。
- 初次 DeepSeek Live（14d0415）：前三轮共三次 HTTP 200。模型正确建立用途待补、更正为备注，最终给对了票号和字段，却把已保存在待补里的内容显式重传为本轮新值，导致来源拒绝和无预览。保留原失败，不把该输入当新版的隐藏验收样本。
- 修正：单票接口明确是补丁而不是状态快照。若模型仅仅误把同字段、仍有效的待补值作为本轮字面提交，且身份/范围已通过，先将旧值从活动状态移除，再在既有预算中只给一次同轮来源修正机会。模型必须重新决定用户是沿用、给了本轮新值，还是需要澄清。仅显式 `value_ref=previous` 才能取回隔离的原来源，后续轮次不可引用这个修正上下文。重复回显、仍无来源、未返回单一动作、超预算，都不会自动采用旧值/生成预览。其他模型工具不开放。

## 边界

语义仍由模型决定，包含某个词串不代表用户授权其关联，更不代表提交许可。企业/账期/票号、fresh 读取、读改权限、真实预览和人工确认守卫保留。多义来源仍须澄清。没有修复高级选集的遗留解析器、自然语言正文可能误称保存，以及已提交记录的撤销问题。

独立复核补充了两个反例：多处未加引号的同一代码不能一并遮盖，从而藏掉新的目标；模型显式提交旧票号而被拒绝时，也不能在下一轮重新继承该旧票。重复字面重叠进入澄清；冲突目标和来源在失败回退中一起失效。未加引号的新值含异票范围，若要继续旧票，工具必须明确选择已绑定的票号，或提供独立票号字面。仍不能从字符串证明模型语义正确：模型如果错误地明确选择旧内容或旧目标，有误预览风险，始终要保留原值和拟改值的人工核对，不能自动提交。

回归新增观察：较早隔离版本在「只查两张、尚未选修改目标」且模型漏传票号时，会把模型错选的字段记成新的活动待补。恢复多票未明确时的拒绝门禁以及现有同层测试；此前已知的单票目标也不能在失败后被沿用。以上只处理范围与状态，不用关键词替模型判断字段。
