# Economy-guy · Agent 工作台

使用 Python 3.11 或更新版本，在 `finance_agent` 目录启动。此版在 Python 3.12 和 Textual 1.0.0 上验证。

```powershell
python -m pip install -r requirements.txt
python main.py
```

也可用 `python main.py tui`。旧数字菜单用 `python main.py home`。原参数子命令继续使用。工作台需要交互终端，建议用 Windows Terminal / PowerShell。

## 首次使用

1. 从账簿读取模拟账号。工作台优先恢复最近成功使用的账簿。找不到时，浏览已有 .db、.sqlite 或 .sqlite3 文件，或从 Excel 创建新账簿。也可用 python main.py --db <路径> tui 指定本次账簿。
2. 打开旧账簿时先查看升级内容。确认「备份并升级」会在原目录创建独立备份，验证后补齐所需结构。升级结果会说明规则是否可用。
3. 在对话区选择「配置 AI 模型」。可选择现有配置或新建个人配置。输入密钥后选择「仅本次使用」或「安全记住在此电脑」。保存使用当前 Windows 用户的凭据管理器，按模型配置区分。设置中也可替换或忘记保存的密钥。
4. 点击「使用此 AI 配置」。状态区分未配置、缺少密钥、连接尚未验证、收到真实响应和最近请求失败。发送真实 AI 消息才会联网，可能产生 API 费用。

「高级诊断」提供固定脚本测试、执行记录和旧数字菜单。更换实际模型连接后，可见聊天会保留，分界标明新 AI 上下文的起点，旧写入许可随会话结束。

## 导航与操作

- 左侧固定显示「对话」「待办」「发票」「记录」「账户」。F2 聚焦当前导航项，F3 打开账户。鼠标可直接点击，Tab 切换焦点，Enter 激活，Esc 取消弹窗。
- 顶部「当前查询企业」可直接选择企业和账期。月份列表显示实际发票和流水数量，可切换年份，也可手工输入其他月份。查询范围只用于读取。每项新的财务修改仍需明确企业。
- 对话可直接问「列出甲企业目前所有发票」或「告诉我甲企业 F002 的发票详情」。目录按日期和发票编号分页，从本轮结果或「发票」进入，选择一行读取详情。
- 「待办 → 新建待办」可选择有修改权限的企业与实际账期。系统核对缺项，填写备注并确认后保存和回读。待办详情与关联发票可离线查看。
- 「新对话」先确认，默认返回，确认后清除可见对话与未提交操作。发票与待办变更使用独立确认，长内容可用 Page Up / Page Down 查看。结果未知时从执行记录核查。

## Live 验收

先确认当前运行使用独立官方虚构库。使用「正常使用（真实 AI）」，发送后在「执行记录」查看真实请求尝试数。遇到模型、网络或权限错误，保留实际结果并停止该场景。离线回归没有消耗 API，真实模型的理解和自然收尾仍须现场复验。

- **A 查询**。发送「帮我查一下甲企业的发票和银行收支情况」，确认追问年月及没有先行月度查询。补充「2026 年 9 月」，核对发票 ¥9,622.06、收入 ¥13,000.50、支出 ¥7,180.74 和 R001 v1.0。
- **B 修改**。发送「把甲企业 F002 的用途改成资料打印」。核对弹窗原值、新值、企业与发票，点击「确认修改」，在执行记录核对成功审计和回读。另起一个修改意图时请重新明确企业。更正已展示的草稿时先取消，再发送完整更正。
- **C 待办**。用独立新库发送「甲企业 2026 年 9 月哪些发票没填用途」，再发送「这些没填用途的发票明天继续，帮我记一下」。核对用户、对象和原始备注，确认保存。退出整个程序并重新打开同一库，选原账号，通过「待办事项」打开关联发票表或「在对话中继续」。补齐 F002 后重新打开表格检查当前缺项 5→4。

## 待办约定

任务归属、企业、账期和类型保存在当前工作库的 `tasks` 表。备注以用户原句预览和确认。工作台只接受原句作为新建、补充和更正时的备注，避免模型添写目标或截止时间。任务备注以业务数据呈现。

创建、范围更正、恢复和完成时重新检查发票修改权限。旧只读用户创建行为已按本轮政策改为拒绝。既有记录仍保留，能否查看取决于当前读取权限。详情链接按当前账号、任务、企业和账期重读 SQLite，显示缺项、发票、关联任务和规则，返回时保留活跃对话。标记完成仍需用户明确确认并重查当前业务证据。

比赛模拟身份、当前会话与持久任务分别管理。完整聊天历史、生产登录与 ACL 管理留待后续阶段。

文字控件采用近黑背景、浅色正文、青蓝动作和琥珀色警示，覆盖登录、导航、设置、待办、表格入口和确认弹窗。输入框仍有清晰边界，聊天区保留自然语言输入和紧凑的业务核验文本。Textual Pilot 在 120×35、90×26 和 80×24 验证了鼠标、键盘、输入框和确认弹窗，并导出界面供复核；Windows Terminal 实机渲染未验证。未发送真实模型请求，P0 Live A/B/C 保留原验收状态，不能视为通过。
