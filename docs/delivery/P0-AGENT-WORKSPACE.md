# Economy-guy · Agent 工作台

使用 Python 3.11 或更新版本，在 `finance_agent` 目录启动。此版在 Python 3.12 和 Textual 1.0.0 上验证。

```powershell
python -m pip install -r requirements.txt
python main.py
```

也可用 `python main.py tui`。旧数字菜单用 `python main.py home`。原参数子命令继续使用。工作台需要交互终端，建议用 Windows Terminal / PowerShell。

启动后选择比赛模拟账号。可在登录前选择、导入或加法升级工作库。验收使用官方虚构 Excel 导入到全新路径，已有工作库保持独立。通过左下角「人」或 F3 打开设置，选择可见 Profile，并核对 Key 是否就绪。可在设置隐藏输入 Key，值只留在进程环境。设置中的「规则、Profile 新增与高级管理」可确认结束当前对话并进入数字菜单。模拟账号可以搭配 Live 或 Mock，真实请求发生在发送 Live 消息时。

Tab 切换焦点，Enter 发送，Esc 关闭弹窗。F2 打开导航，F3 打开账户，F4 取消当前未提交意图，Ctrl+Q 退出。发票和长期状态变更使用独立确认弹窗，初始焦点在「取消」。已提交但结果未知时从「执行记录」核查成功审计。

## Live 验收

先确认当前运行使用独立官方虚构库。明确选择 Live，发送一次后查看「执行记录」和底部真实模型尝试数。遇到模型、网络或权限错误，保留实际结果并停止该场景。离线回归没有消耗 API，真实模型的理解和自然收尾仍须现场复验。

- **A 查询**。发送「帮我查一下甲企业的发票和银行收支情况」，确认追问年月及没有先行月度查询。补充「2026 年 9 月」，核对发票 ¥9,622.06、收入 ¥13,000.50、支出 ¥7,180.74 和 R001 v1.0。
- **B 修改**。发送「把甲企业 F002 的用途改成资料打印」。核对弹窗原值、新值、企业与发票，点击「确认修改」，在执行记录核对成功审计和回读。另起一个修改意图时请重新明确企业。更正已展示的草稿时先取消，再发送完整更正。
- **C 待办**。用独立新库发送「甲企业 2026 年 9 月哪些发票没填用途」，再发送「这些没填用途的发票明天继续，帮我记一下」。核对用户、对象和原始备注，确认保存。退出整个程序并重新打开同一库，选原账号，通过「待办事项」打开关联发票表或「在 Agent 中继续」。补齐 F002 后重新打开表格检查当前缺项 5→4。

## 待办约定

任务归属、企业、账期和类型保存在当前工作库的 `tasks` 表。备注以用户原句预览和确认。工作台只接受原句作为新建、补充和更正时的备注，避免模型添写目标或截止时间。任务备注以业务数据呈现。

创建、范围更正、恢复和完成时重新检查发票修改权限。旧只读用户创建行为已按本轮政策改为拒绝。既有记录仍保留，能否查看取决于当前读取权限。详情链接按当前账号、任务、企业和账期重读 SQLite，显示缺项、发票、关联任务和规则，返回时保留活跃对话。标记完成仍需用户明确确认并重查当前业务证据。

比赛模拟身份、当前会话与持久任务分别管理。完整聊天历史、生产登录与 ACL 管理留待后续阶段。
