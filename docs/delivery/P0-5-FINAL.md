## 缺用途查询复核

只读检查了本机 TUI Trace。与描述相符的两轮都标为 `mock`，都没有 `api.response`。第一轮的模型输入确实有甲企业 C001 的 2026-09 可信工作区，旧脚本仍追问。第二轮用户补年月后，脚本请求 `get_finance_summary(C001,2026,9)`，Handler 返回 `SUCCESS`，最终内容为实际汇总。旧 Mock 只检查最新输入有无年月，随后固定请求汇总。这解释了匹配记录中的表现。文件中也有其他 Live 轮次及 API 响应，未找到能证明同一异常由真实 DeepSeek 执行的对应记录。历史 Trace 原样保留。

固定脚本现在读取可信范围，按受支持的缺用途和收支示例提出对应工具，其他请求明确提示需要真实 AI。Live 仍由模型选择工具。工具描述与上下文明确区分用途缺项和财务汇总，当前明确要求优先。界面从 `check_missing_purpose` 的真实结果展示日期、编号、缺项数及规则版本。新的轮次起始事件记录实际是否绑定传输，便于将界面模式与 API 响应对照。

## 持久会话与偏好

此前 Context Builder 选择进程内整轮消息和可信展示锚点。现在 TUI 将可见历史按轮写入独立 SQLite，会话以可信账号、账簿 UUID 与实际文件身份隔离。Windows 默认存储位于 `LOCALAPPDATA/Economy-guy/conversations.sqlite3`。首次开启时在账簿添加单行身份表。已复制或换成不同身份的文件打开独立会话。同文件身份且同 UUID 的备份仍视为同一谱系。

登录自动显示上次可访问的对话。新 Agent 只接收预算内最近查询的用户原话、工具类型和只读范围线索。旧显示金额与数量保留在聊天中供查看。真实引用、任务、权限和当前业务值由现有服务重查。更换模型写入上下文分界。新对话仍先确认并归档旧对话。正式执行仍使用 `Agent.ask`，单轮硬限保持 9/12/2/1。

轮次开始先写 `RUNNING`。崩溃释放同会话文件锁，重新登录将未结束查询标为 `INTERRUPTED`。发票确认后、提交前写入 `UNKNOWN_OUTCOME` 和审计查找编号。恢复从现有 SQLite 审计与当前状态核实，状态无法确定时提示检查。运行时草稿、授权、指纹、计划及私有模型消息不进入会话存储。恢复没有重放执行步骤。

在「账户 → 工作台设置 → 业务数据 → 偏好设置」可查看或更改个人回复习惯及企业偏好。个人回复详细度按本机模拟账号与账簿保存。企业偏好继续由现有按用户和企业隔离的 Preference Store 持有。设置和自然语言候选都显示具体内容，用户确认后保存并回读。偏好只作为低信任表达数据，当前明确要求优先。
