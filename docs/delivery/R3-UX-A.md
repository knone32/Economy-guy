## 三项改动

- **对话展示**　`tui.py` 区分用户和 Agent 角色，查询卡、发票回执及待办结果用紧凑 Rich 边框。在同一可信范围内合并完全相同的数据和卡片，保留不同页、范围、规则和执行记录。旧会话仍按原角色和正文回放。
- **AI 恢复**　`tui_screens.py` 仅在明确选用或新建并使用后请求记忆。`tui_local.py` 按模拟账号和既有账簿身份原子保存 Profile 名称。最近账簿 JSON 格式、Profile JSON 和凭据入口沿用原实现。缺少密钥时提示设置。上次 Profile 不存在、无权读取或无法加载时提示重选。恢复不发送请求，也不恢复草稿、授权或模型私有消息。
- **顶部状态**　`tui.py` 与 `tui.tcss` 分开显示预选只读范围、最近可信查询焦点和当前待办焦点。`tui_sessions.py` 从权限过滤后的会话记录恢复最近焦点，切换账号、实际更换模型及新对话会清理显示焦点。焦点只供展示，查询仍按既有规则重新鉴权和读取。

## 验证

`tests/test_r3_ux_a.py` 在基线复现 **3 个预期失败**。最终定向 36 项、全量 unittest 451 项及独立架构测试 2 项通过。首次定向组有一次旧待办 Pilot 在焦点就绪前取值，原用例单独复跑和最终定向组均通过，未调整旧断言。Mock 与 Pilot 覆盖 80×24、90×26、120×35、历史回放、同证据去重、重登及新进程恢复、账号与复制账簿隔离、已删除 Profile 拒绝回退、显式更正和对话分界。原有定向用例覆盖可信确认、成功审计、回读、任务恢复和权限拒绝。真实外部模型 API **0 次**。正式账簿、试用账簿与用户本地 Profile 文件的校验值一致。

## 人工复验

用虚构账簿在 Windows Terminal 分别打开三种尺寸。检查边框换行和上下滚动，确认用户与 Agent 标题易于区分。显式选用一个 Profile 后关闭程序，以原账号重新登录并核对未联网状态，再切换账号或复制账簿确认隔离。以只读模式核对预选范围和最近焦点可同时显示不同值，再检查新对话后的失效。真人终端外观和真实模型连接未在本轮验证。
