# 一次财税问答怎样得到可核对的结果

在 Submission-R2 的真实 DeepSeek 场景 A 中，用户先问“帮我查一下甲企业的发票和银行收支情况”。工作台追问账期。用户补充“2026 年 9 月”后，界面给出发票价税合计 9,622.06 元（10 张）、银行收入 13,000.50 元（4 条）、银行支出 7,180.74 元（8 条），依据 R001 v1.0。独立 SQLite 查询得到相同数值。另一次在工作台预选 C001 和 2026-09 后，模型直接查询并显示同样的结果。[本轮证据](SUBMISSION-R2.md)

## 从问题到结果

1. **输入进入工作台。** `AgentWorkspace.submitted` 接收输入，取当前登录的模拟账号、账簿和只读工作区。`run_turn` 调用唯一生产入口 `Agent.ask`。
2. **上下文给模型最少的可靠信息。** `ContextBuilder` 在预算内选取完整近期轮次。A1 只有甲企业，没有可靠年月，所以需要追问。A2 的补充和上轮企业共同确定 C001／2026-09。预选测试则使用已经鉴权的只读工作区。选择这些线索能省去反复输入企业和月份。
3. **模型选择工具，程序负责执行。** DeepSeek 读到工具清单后提出 `get_finance_summary` 及企业、年月的 JSON 参数。Tool Registry 检查参数类型和完整年月、请求范围与当前账号的读取权限，按工具 ID 配回结果。模型无法仅靠输出文字得到权限。
4. **工作台根据执行证据展示。** 查询服务从当前 SQLite 读取发票和流水，按 R001 口径分别统计。`responses.render_information` 和工作台业务卡片展示真实工具结果。独立 SQL 可以再算一次，因此金额、笔数和规则可以脱离模型答复单独复核。

## 写入和长期任务怎样区分

发票修改先由模型提出 Prepare。`WriteCoordinator` 管理当前草稿，工作台显示企业、发票、字段及新旧值，等用户确认这一个草稿。`updates.commit_invoice_update` 在事务中再次核对权限、内容和旧值，连同成功审计一起保存，然后用新连接回读。旧确认不跨轮或跨进程继承。本轮自动按确认按钮的证据标为 `SIMULATED_CONFIRMATION`。

`Task Manager` 管理 SQLite 中可跨进程恢复的待办。`TurnExecution` 只跟踪当前一轮的计划、计数和停止条件。重启后可以按任务 ID 找回待办，再查现有发票确定进度。本轮计划和待办生命周期分别结束。

## 从证据还原执行过程

查询先对照脱敏 Trace 的 `model_reply`、`tool_result` 和 `turn.finished`。工具 ID 把提案与结果连起来，执行计数和停止原因说明这一轮走到了哪一步。写入再按请求编号在 `invoice_audit` 核对目标、字段、新旧值与指纹，并从新连接读当前值。Trace 说明经过，审计和回读证明业务变化。
