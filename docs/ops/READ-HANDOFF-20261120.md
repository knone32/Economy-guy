# 待补单票转查询

`Agent.ask` 接收有效的旧 `intent.action=read` 后，将它仅作为转查询提案：通过原 `pause_invoice_update` 撤销执行状态、保留未批准单票，逐 ID 配对该消息工具但不执行，再进入同一 Loop 的独立 BusinessRequest 阶段。语义输入不含该 intent 的目标或工具提案；旧票号、月份和修改内容不自动继承。新只读要求不能返回 legacy，也不能提交暂挂修改。

`business_request.context_transition` 是 Runtime 参数，保留有效前文来源核对和修订引用；不接受模型自行声明。普通续查仍保留防止静默删筛选的检查。草稿、候选持久化、恢复 CAS 和确认继续归原协调器及 SessionStore 所有。

另修 `WriteCoordinator.read_basis` 的生命周期：只有当前有效待补，或与真实待确认草稿完全匹配的回执才可供 fresh 单票读取。取消、终态回执及旧 allow_prepare 布尔值不能充当依据。
