# 只读工具契约与投影

`tool_contracts.ToolSpec` 是纯静态声明，不导入数据库、Agent、分发器或结果适配器。原处理函数及参数、普通工具暴露、财务读取分类、结果适配 ID、对象及条件能力、范围模式集中在同一注册条目。`REGISTRY` 仍派生为原来的二元 tuple；处理器只绑定原已导入服务模块，不动态导入模型提供的名称。

Agent、delivery、provenance 和旧 intent 接口从这里派生各自集合。迁移前后的 10 组声明完全相同，仍只有原 6 项业务要求结果适配；分页、引用及未适配统计没有自动获得新能力。SQL、单票、月度、年度、目录、引用各自既有特殊范围检查不变。声明只限制能力上限，不能建立 BusinessRequest、ACL、read_basis 或执行证据。

投影归因按 AST 区分 detail、aggregate、grouped、window、distinct，未知行效应拒绝。未证明的输出列不再因缺少单位而被误判为聚合。已有确定性 `is_blank(单个原字段)` 保留支持，其余未知函数及非法签名不作为可丢弃展示列。

明细降级要求：原 source rows、查询对象、期间、全部条件及原联合键/日期可核对，仅未证明的标量展示列可移除；原 SQL、原行及列映射保留。完整原字段和完整行集才为 details-* 建立覆盖证明；末答必须真正引用本轮结果。缺原身份列、未知聚合/窗口及 DISTINCT 的不完整投影继续报告能力限制，不显示为已完成业务。没有重新计算金额或给换算表达式授予事实资格。

本地定向与架构组合检查为 140 项；组件、程序链和模型 Live 分开记账。原 O01 FAIL、O02 PASS、整对 FAIL 保留，未重放。显式准备会话中的汇总后准备、旧通用 pending、安全真人批准和重启回读仍有缺口；本声明收拢不代表新工具仅加一个名字即可完成全部执行和界面接入。
