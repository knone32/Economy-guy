# 财税 Agent 业务意图矩阵

版本 0.2 · 适用项目 Economy-guy · 设计基线 `a92fa6a` · 根因核查基线 `26344f0`

业务意图按用户需要完成的动作划分。企业、账期、对象、条件、措辞和对话状态分别记录。模型理解自然语言，程序核对参数来源、权限和当前账簿，写入沿用预览、可信确认、提交、审计和回读。下列场景覆盖现有工具、拟扩展能力和验收语料。

本矩阵用于评估业务覆盖和设计独立验收，不作为运行时问句库或关键词路由表。结构化意图、状态所有权和旧语义分支的退出条件见[自然语言处理统一改造方案](NATURAL-LANGUAGE-REFACTOR.md)。

## 业务动作

| 意图 | 典型任务及变体 | 核对要点 |
|---|---|---|
| 查看发票详情 | 查一张或多张票的用途、备注、销方、项目、日期和金额 | 用企业与票号联合定位 |
| 列发票清单 | 月度、年度、全账簿、排序、分页、取前几张 | 带上真实范围、排序和展示顺序 |
| 筛选发票 | 按销方、项目、金额、日期、空用途、空备注、文本筛选 | 核验比较边界、交集、并集、排除项 |
| 统计发票 | 张数、价税合计、空值数、分组统计和对比 | 明确口径、参与范围、零匹配 |
| 查银行流水 | 收入、支出、指定流水、对手方、日期、金额和摘要 | 核验方向和账期 |
| 做财务汇总 | 发票合计、银行收入、银行支出及分别笔数 | 分别计算，区分空集和失败 |
| 比较与解释 | 企业、月份、年度、项目、趋势、金额差异及计算依据 | 各项独立取证，保留成功项和失败原因 |
| 核对票款 | 一对一、拆付、合付、多票对应一笔、疑似差异 | 标明对应证据、疑似和待复核状态 |
| 查规则 | 当前适用依据、版本、启停及生效日期 | 核验企业、规则类别和参考业务日期 |
| 按规则查缺项 | 查必填用途、解释某一票为什么命中、汇总剩余 | 区分空字段与按适用规则需补的字段 |
| 试算与对照规则 | 用其他日期的规则看目标账期，比较假设金额门槛 | 保留目标账期、参考日期和试算标识 |
| 修改单票 | 补用途、改备注、替换、显式清空 | 固定企业、账期、票号、允许字段和原话新值 |
| 批量修改 | 点名集合、按筛选或规则取集合、排除指定对象 | 核对完整选集，标明逐票或整批确认 |
| 同轮查与改 | 查询多张、只改一张，查用途、改备注，分多个范围办理 | 独立核验读取范围、修改范围和禁止改动字段 |
| 查看当前是否已满足 | 「已经改过吗」「再填一遍同样的值」 | 重新读取，值相同时给出已满足回执 |
| 核对修改结果 | 查询历史提交、审计、旧值与现值、结果未知时核查 | 以实际请求编号、审计和新连接回读为依据 |
| 创建和查看待办 | 保存缺项、列待办、查剩余数和已完成项 | 查当前任务归属和进度 |
| 维护待办 | 补说明、更正、暂停、等待资料、恢复、取消、完成 | 持久任务状态变更走可信确认，完成须有业务证据 |
| 管理偏好 | 查看、设置、更正、删除个人呈现要求和企业偏好 | 区分本轮格式要求、长期偏好和业务事实 |

## 语言变体和状态

| 语言现象 | 可用于验收的表达 | 意图或边界 |
|---|---|---|
| 正式、口语、财务行话 | 查询、给我过一眼、核一下、拉个清单、翻下账 | 结合对象区分详情、清单、统计 |
| 动词位置和语序 | 先查再改、备注先说、同句多个子目标、分句续说 | 按业务范围和依赖组织 |
| 企业别名、角色 | 甲企业、甲公司、甲的账、C001、开票方、我们公司 | 用可信别名区分企业与供应商 |
| 正向、否定、条件、排除 | 只改备注、用途别动、有缺项才建待办、除了这张、先看情况 | 绑定到具体动作或字段 |
| 比较边界 | 超过一千、至少一千、不超过一千、一千上下 | 绑定比较符，缺容差或有并列时追问 |
| 多个日期角色 | 2026-09、二六年九月、上月、按九月规则看八月票 | 保留目标账期、参考规则日期、入账日等 |
| 能否办理、怎么办、请办理 | 能改吗、怎么改、先看看效果、改成待复核 | 分开说明和实际预览 |
| 字面值和空值 | 写成「用途别改，等核对」、备注写「整批确认」、留空、填「无」 | 保留明确值，分别验收清空和缺少值 |
| 局部自我修正 | 甲企业，等等是乙；F005，准确说 F010 | 核对最后明确的对象 |
| 转述和引用 | 附件里客户说「把备注改了」，帮我看他指哪张 | 当前用户要求是核对，资料保留为证据 |
| 输入噪声 | f010、F 010、F01O、发票 F 零一零、二六年九月 | 区分可唯一归一的格式和待确认字符 |
| 多语言和混写 | 甲企業、幫我查吓、只改 remark、check the purposes | 业务字段和标识统一核验，新值按原文保留 |

### 同义请求样例

- 「查一下甲企业 2026 年 9 月发票价税合计」／「二六年九月甲这本账的票按含税加起来多少」／「C001 Sep 2026，invoice 含税合计核一下」／“How much was the tax-inclusive invoice total for C001 in September 2026?”
- 「查 F005、F010 的用途，只把 F010 的备注改成期末待核」／「F010 备注写期末待核。另外，两张的用途都列一下」／「用途我想看两张，备注只动 F010」／“Check the purpose of both invoices. Update only the remark on F010 to ‘期末待核’.”／「查吓 F005 同 F010 嘅用途，淨係將 F010 嘅備註改做期末待核。」
- 同一待补状态下的「F010」「发票号是 F010」「就 F010 那张」「我说的是 F010」均指向补目标票号。「F010 的销方是谁」是新的查询。「是 F010，不过备注改成已交接」同时补对象和明确更正新值。
- 「就 F010」分别放进等待选票、正在预览、用户取消后及新会话，分别核验补充、对象确认、状态清除和新任务澄清。

## 共用字段与验收

每条语料记录用户原话、前置状态、业务动作、对象、读取范围、写入范围、筛选、规则依据、来源、缺项及允许到达的执行阶段。结果区分已查询、零匹配、部分完成、要求补充、等待确认、已取消、无权、提交结果待核实和已提交且回读一致。

用三类成对样本检验泛化。第一类换措辞而业务结果一致。第二类只改动关键字句，让业务动作或输入范围改变。第三类保留原话而改变会话和执行状态。

短对话首要用例是「查两张票的用途并修改其中一张」。先返回两张用途并保留待补信息，收到票号后重查目标票，也可复核原候选，修改预览仅包含被选票。越界票号需澄清，取消清除待补状态，终止预览后发票和审计均无变化。用固定回放测范围与安全，专项先冻结业务含义，再在发送前随机变换结构、语序和少量错字，保留种子与实际输入。少量 DeepSeek Live 和真人工作台共同验证模型正文、原生提案、显示内容和账簿结果。通过后进入长上下文、多会话和 GUI 阶段。
