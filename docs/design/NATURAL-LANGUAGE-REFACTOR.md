# 财税自然语言处理统一改造方案

2026 年 11 月 18 日实施修订。沿用单一模型循环与已有业务工具，先修模型正文、待补状态、独立读写范围。运行代码修复前基线为 `26344f0`。不增加或强制调用意图声明工具，不在所有工具上增加统一意图参数。

## 一 与既有准则对齐

工程总纲及 [S4-P0C 历史对比](../verification/stage4/S4-P0C.md) 记录过小样本 Intent A/B：两组均完成，Frame 增加 token 和耗时，生产未实施强制抽取。本轮不以旧实验证明一切结构化协议无用，也不绕过旧结论强制上线新声明工具。

普通查询保持直接 Tool Calling。模型理解动作、角色、追问及回复，Harness 检查可信身份、对象来源、权限、范围、确认与审计。业务矩阵用于覆盖和独立验收，不进入运行时问句匹配库。

## 二 本轮实现边界

| 功能 | 改动与约束 |
|---|---|
| 模型正文 | 保留 `assistant_text`，工作台直接显示；现有 `text/chat_notice` 兼容接口可附带独立系统结果，不能覆盖正文。 |
| 证据冲突 | 对本轮事实中的标识、数字和查询范围做可机检核验；明确冲突时保留原始 Trace，标记正文拒绝，只显示工具实际结果，不假称模型成功回复。该检查不证明任意自然语言语义正确。 |
| 待补状态 | 保存原始要求、全部有效缺项、范围、当前账号、账簿与请求编号，保存不再受 `invoice_write` 句式判断限制。追问信封可选 `pending_change={field,new_value}` 保存已知字段与原文新值，核验后才能供接续提案引用。 |
| 待补接续 | 模型在既有提案上可引用 `pending_request_id`；重新读取当前票据，核验原候选和字段新值来源。无引用不能凭相同关键词恢复修改。 |
| 待补取消 | 最终回复可带可选 `pending={request_id,action}`，只操作指定待补项。可信按钮、命令与草稿确认机制继续保留。 |
| 读写范围 | 既有 `propose_invoice_changes` 可选 `write_scope`，仅复杂查改需要；校验联合键、原文对象、本轮 selection、账期、排除项及字段新值。 |
| 旧能力 | 保留现有查询、规则、任务、偏好、确认、事务、幂等及审计回读接口。已有明确范围与保留约束仍生效，不以新参数绕过旧有效约束。 |

`write_scope` 只描述企业、年月与实际修改票号；它是候选语义数据，不是身份、授权或提交凭证。已有提案字段继续表达新值和确认方式。普通查询无须携带此字段。

结构化修改范围绑定后，以原文同一分句中的字段与字面新值，或已核验的待补字段新值记录，核对内容来源；不再要求命中正向修改动词。引号内的新值整体屏蔽，避免把值里的“用途”“备注”当字段来源。既有否定、转述、字段白名单和确认边界继续检查。这是有边界的来源绑定，字段错别字等更复杂来源仍需后续独立专项。

复杂查改提案遗漏独立范围且遇到范围冲突时，针对单条提案最多返回一次可补正的 `INVALID_ARGUMENTS`，由同一模型补充现有参数。只在尚未生成草稿、真实选集仍有效时允许，全部调用照常计数；不放宽权限、其他范围错误或全局停止策略。重复缺参即停止。

待补记录是当前会话数据，不能复制或取代 Task、Preference、Context、Reference、Scheduler 和草稿所有者。当前新查询结束后，不带接续引用即不继续旧修改。复杂话题挂起、多会话并发与长上下文扩展后续单独实现。

## 三 本轮暂不扩大的范围

不建立通用操作 DAG、第二模型、分类器、完整筛选语言、意图数据库或新控制器。不把全部自然语言入口一次重写，不迁移未涉及的任务与偏好状态，不扩大受限只读 SQL 权限，也不实施 GUI。

现有部分句式适配和字段来源检查仍属于遗留实现。本轮不追加动作同义词、问句或正则例外。尚未迁移的补票 FastPath 等路径继续登记为 OPEN，不能把三项修复包装成全项目自然语言泛化完成。

来源引用能够证明消息与值存在，不能证明模型对转述、否定或条件的理解正确。错误预览同样判 FAIL。数字字面量核验不能证明每个数值在正文中的业务归属或任意计算正确，验收必须继续比较范围与独立数据库真值。

## 四 分段实施和验收

先建立正文丢失、待补丢失、独立修改范围被拒绝三个失败反例，再分别修正。每段保留现有安全断言，不以删除失败场景通过验收。旧测试中原由 Harness 解释的自然语言取消、补号，改为模拟模型给出对应结构化结果；Live 仍使用未强制工具的自然输入检验真实理解。

仅运行相关定向回归，覆盖查询正文实际进入工作台、追问与新查询、补号、取消零写入、错票/错字段/错账期/越权拒绝、双票和 SQL 选集、提交审计回读以及架构依赖。保留相关安全测试，不跑全量回归。

之后使用固定代码版本、小批 DeepSeek `shared-flash` Live 和隔离账簿。业务预期先冻结，每次发出前随机调整句式、顺序和少量非关键值错字，保留种子与实际输入，不择优重跑。首批最多 12 次模型请求，遵守单轮原有硬限，比赛 API 调用为零。

确定性、真实 API、工作台自动操作和真人验收分别报告；少量 Live 不代替真人测试。先完成本次范围，再推进长上下文、多会话，GUI 最后。
