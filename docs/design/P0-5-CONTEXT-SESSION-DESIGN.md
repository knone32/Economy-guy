# P0.5 会话与上下文设计

| 状态 | 权威所有者 |
|---|---|
| 可见历史、恢复边界、活跃会话和只读焦点选择 | 本机独立 SQLite Session Store |
| 当前模型消息、可信范围与选择 | Agent Runtime 持有消息，Context Builder 选择和限长 |
| 实际展示引用 | Reference Resolver，按本会话曾完成的展示 ID 检索并重查 |
| 持久任务、企业偏好 | 原 Task Manager、Preference Store |
| 个人展示偏好 | Session Store 的独立用户偏好表，按模拟账号及账簿隔离 |
| 单轮计划、身份与写入许可 | Scheduler 与现有可信运行时 |
| 当前金额、发票、规则、修改审计 | 财务工作库的现有 SQLite 服务 |

Session Store 位于本机应用目录，独立版本。每个账簿和用户只打开一个活跃会话。账簿首次启用持久化时在原库添加一张单行 UUID 元数据表，并将 UUID 与实际文件 ID 组合。新库、文件复制和不同 UUID 覆盖会隔离。保留同一文件 ID 与同一 UUID 的原样备份属于同一账簿谱系，启动时照常重查权限和事实。只读或无法写入标识的账簿降级到进程内会话。运行中发现文件标识变化时停止使用旧会话，要求重新打开。旧 CLI 和测试可不启用会话存储。

保存边界是一轮真实 TUI 操作。发送前事务写 RUNNING 和脱敏用户输入。完成时事务保存显示文本、工具名称/ID/状态/范围、可用展示 ID、只读语义线索及上下文边界。模型切换增加分界并重置语义选择位置。持久化从真实显示出口提取数据。原始模型栈、私有推理、凭据、原始 Trace、旧草稿、确认、指纹、计划和权限结果均不属于该数据结构。

恢复前验证当前账号、账簿与企业访问。可见历史按轮显示，失去权限的企业历史隐藏。创建全新 Agent，选择最近至多六轮已完成且获准的查询用户原话、工具类型、范围作为标记为历史的数据。历史可见业务值保留给用户查看，模型获取的恢复线索不含旧业务结果。Context Builder 继续按原预算保留必要消息和完整真实协议轮次。可信选定焦点或已实际验证的最近唯一月度查询焦点可供只读续问，当前明确企业和账期优先。任务仅由真实 ID 重新读取。引用需仍活跃、已展示、当前有权且联合键当前有效。

进程以 OS 文件锁独占同一账簿和账号的会话。崩溃释放锁，下次登录将 RUNNING 标为 INTERRUPTED。确认发票写入后、Commit 前先将轮次标为 UNKNOWN_OUTCOME，仅保存审计查找编号。恢复用当前 SQLite 审计及回读报告已知结果，其余提示需核实。中断轮次永不重放。关闭窗口无需执行额外保存。开始新对话以事务归档旧活跃会话并创建新 ID。

偏好设置复用原企业偏好服务及其可信具体内容确认，个人回复详细度由独立本地设置维护。向模型提供当前相关企业的偏好和本机个人回复习惯，均为低信任数据。自然语言保存使用现有企业偏好确认路径，缺少唯一企业时追问。当前明确要求优先。

与架构契约核对：单一 Agent.ask 与 9/12/2/1 预算保持，运行层依赖业务服务，业务表、授权及审计所有权保持。新增账簿身份表和独立本机会话表只负责恢复隔离与显示资料。
