# 读取要求与交付核对（第一步）

实现入口是 `Agent.ask` 的业务工具分发边界。现有 Loop、请求/工具预算、任务、待补及正式草稿的 owner 不变。

## 状态与依据

`business_request.py` 持有不可变 `BusinessRequest`：当前用户来源、修订号、企业、期间、对象/集合关系、条件、指标、分组、比较和未决项。要求判定独立发起，输入只有原话、有效前文、可信范围和当前可读目录；不包含拟执行 SQL、执行器参数或历史金额。它仍是模型解释，不是语义证明或授权。

Runtime 核对企业/销售方登记、ACL、原话来源、有效前文和对象唯一性。简称不唯一时先交付候选及追问。明确集合与单家身份分开；无销售方参数不代表可以丢掉要求中的销售方。

工作台的 `task_note_from_request` 只是说明来源选项，不能用来跳过读取要求。明确管理操作和发票办理仍由原入口处理。

结构或类型错误只有在合法 `kind=read` JSON、原模型预算仍有槽时，沿用现有 Loop 进行至多一次结构重述。重述仅接原独立输入及有限静态错误码，不接失败模型回复、SQL 或工具提案；严格绑定仍是接受门。重复键、截断、权限/来源/范围冲突和真实歧义不走此路径，重述不能改成其他业务路线，也不能执行工具。

## 执行及展示

`business_request_delivery.py` 登记已适配只读工具的能力并核对实际结果，Registry 在执行前和结果进入卡片/事实目录前调用它。当前适配受控 SQL、月/年度财务汇总、发票列表/单票、银行流水列表；其他业务工具不得借同一要求绕过契约，返回明确能力限制。

- 专用汇总/列表不能落实销售方等附加筛选时，在后台调用前拒绝。
- SQL 来源证明和满足用户要求是两个结论；未知证明能力与已核实范围冲突分开。
- 金额、数量、期间、条件及分组均依据真实查询归因和结果维度核对，不信任 SQL 别名。
- 日期谓词不能把半月冒充整月。条件聚合里的筛选也参加核对。
- 可验证的固定维度只投影原始单元格，不重算金额。未要求的细分维度只能作为对象线索，删除金额/数量标量，不当所需合计。
- 结果保留当前要求修订/hash、执行范围、投影映射和读取版本证据。文件时间戳/快照 hash 不等于全账簿统一事务版本。

`assess_results` 汇总当前修订接受的执行证据，不能用工具名或模型的“已完成”宣布覆盖。`assess_selection` 再将末答当前事实引用绑定到同一修订的指标、范围、口径和实际分组；比较必须符合要求中的运算及左右期间。反向/错运算进入已有最终引用补正流程，不能展示为所请求差额。遗漏允许交付真实部分，但明确未完成；计算父值没有实际展示时不计入分期金额交付。执行覆盖与末答交付覆盖分别保留。

## 有限范围

读取要求可继承有效只读前文。默认 `relation=update` 防止静默丢失旧筛选；明确 `replace` 需要当前原话和有效 `previous_target_id`，记录被替换修订来源；`clarify` 保留未决。此关系尚未接管原修改草稿/批准状态。后续办理接入应关联现有修订 owner，不复制草稿管理器。新增 Skill 复用原工具；新增 Tool 需要真正的能力、权限、范围/单位/完整性证据及展示适配。已建立读取要求后，生成器仅看见已登记结果契约及辅助工具；未适配工具保留明确能力限制，不当作已支持。
